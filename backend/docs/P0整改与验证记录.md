# 场馆管理平台 P0 整改与验证记录

## 已完成

- 预约创建通过 `venue` 行 `FOR UPDATE` 串行化同一场地的冲突检查与写入，避免并发下先查后插导致重叠预约同时成功。
- 普通用户的预约查询范围从 JWT 登录用户获取，创建预约不再信任请求体中的 `userId`；取消、签到、离店、支付只能操作本人预约。
- 审核和缴费状态修改仅允许管理员角色；设备租借、归还和租借列表也仅允许管理员操作。
- 离店要求预约处于 `APPROVED`、已有签到且尚未离店；重复签到和重复离店会被拒绝。
- 设备归还使用条件更新 `status = 'RENTED'`，只有更新影响行数为 1 时才回补库存，重复并发归还不会重复加库存。
- 按小时计费改为 `BigDecimal` 计算，按 0.01 元、`HALF_UP` 舍入；预约编号改为 UUID 后缀并保留数据库唯一约束。

## 验证

- `BookingInvariantTest`：验证 90 分钟计费为 52.50 元、场地锁定调用、未签到不能离店，共 2 项通过。
- `EquipmentRentalServiceTest`：验证库存扣减、库存不足、归还和重复归还，共 4 项通过。
- 后端本地全量测试 46 项通过、0 失败；其中 2 项真实 MySQL 并发测试单独执行并通过。
- 独立 Docker MySQL 8.4（`localhost:3308`）验证通过：两个线程创建同一场地同一重叠时段预约，恰好一个成功；两个线程归还同一租借记录，恰好一次成功且库存只回补一次。

## 尚未升级的表述

当前实现覆盖预约核心状态前置校验，不宣称已实现完整预约状态机；普通用户身份覆盖、管理员审核限制已通过控制器授权测试，JWT 过滤器负责将登录身份注入请求上下文。
